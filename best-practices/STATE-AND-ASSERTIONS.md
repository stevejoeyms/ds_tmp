# 通用规则：状态、作用域与验证

这些规则适用于已登录浏览器中的黑盒UI操作。它们是从现场反馈提炼的方法，不包含站点地址、业务数据、特定组件类名或固定操作序列。

## 1. 把状态分成三层，再行动

**输入层 → 提交层 → 业务生效层。** 输入框显示新值，只证明输入层变化；组件内部状态、表单提交和结果刷新可能尚未完成。

通用步骤：观察原值 → 通过获准UI方式输入 → 按现场已确认的方式提交/确认 → 重新观察有效值 → 执行获准业务动作 → 核对结果与有效条件一致。不把fill完成、失焦、关闭面板或按键成功单独当作生效证明。

控件可能格式化、截断、过滤或规范化输入。记录输入意图、实际保留值及业务预期；三者不一致时先解释原因，不能继续用原输入构造断言。不要直接修改DOM或框架内部状态来制造“已生效”。

Enter、失焦、点击确认等都是可能的提交方式，不是跨组件的固定处方。先确认当前焦点和动作后果，再使用；不把某次实测推广到所有控件或版本。

## 2. 身份与作用域先于选择器

依次确认：测试环境 → 当前tab → frame → 活动区域/面板 → 控件。只有控件匹配到一个正确、可操作的目标，才执行动作。

相同文案可能同时存在于多个面板、隐藏副本或多个frame中；“找到两个”不是靠first()解决的理由。先根据当前任务、活动面板及可见性收窄范围，再观察目标。可见性也不能替代业务身份确认。

图标按钮没有innerText，不代表没有可访问名称。优先检查真实快照target、role、aria-label、title和上下文；确实缺少稳定语义时，才使用已观察并确认唯一的选择器。不凭UI框架名称猜类名。

## 3. 等业务就绪，不等偶然结构

**导航返回、frame出现、元素数量达标、loading消失，都不单独证明业务已就绪。** 对本次操作定义有意义的条件：正确frame/区域、目标控件可操作、相关加载状态完成，以及结果可核对。

等待必须有截止时间，超时报告具体未满足条件。通用手册不写死某个站点的控件数量、轮询间隔或历史总数；固定sleep只能作为有限辅助，不能替代就绪证据。懒加载、重绘或frame替换后重新定位，不长期持有失效目标。

## 4. 用实际边界诊断，不用表象下结论

URL路径不同不等于跨源。同源由scheme、host、有效port决定；还要考虑真实重定向目标和sandbox造成的不透明源。读不到iframe内容时，分开检查：选中的对象是否正确、frame是否已挂载/替换、实际URL/来源、浏览器权限与工具能力。

优先使用已授权的Playwright frame/快照能力，不通过取消sandbox、关闭同源保护或换成直接业务API来绕过问题。页面只展示导航，也不代表业务空白。

同理，错误文案中的浏览器名、资料名、诊断提示是线索，不是事实本身。先用可观察界面、版本和实际加载状态交叉确认。不要为确认扩展就遍历/导出整个浏览器用户资料或凭据。

## 5. 默认值、重置和空值分开定义

**重置通常意味着恢复产品约定的默认状态，不必然等于清空所有值。** 必填、默认非空、保留上次选择等行为是否正确，需要产品契约或明确预期。

动作前记录基线和预期，动作后逐项比较。只知道“字段没有清空”，还不能确定是产品缺陷。没有业务依据时记为待确认/INCONCLUSIVE，而不是同时写“疑似缺陷”和“全部通过”。

负向输入被过滤也可能是合法校验。核对需求所要求的拒绝、提示或规范化行为，再判定，不把测试脚本与页面假设不一致一律当作产品Bug。

## 6. 交叉验证要核对身份和内容

**总数一致是必要线索，不是完整正确性证明。** 对分页、详情和获准导出，需要在相同有效筛选、排序、权限、环境及合理时间窗口下比较。

先辨明唯一记录标识，再检查遗漏、重复、错配和关键字段；分页数量之和相同仍可能存在重复与遗漏。导出核对实际数据sheet、表头与数据行边界、筛选范围和必要字段，不把文件大小或多sheet总行数当作业务正确性证据。

明确日期/时间的时区和起止边界；不从显示日期自行推断后端是闭区间、半开区间或结束日零点。并发更新影响结果时记录限制，不以动态总数变化自动判失败。

不要为了交叉验证重复触发有副作用的任务。导出授权、文件保存位置与数据保留范围要单独确认。

## 7. 观测范围限定结论范围

“未观察到console error”只覆盖实际连接后的采集窗口、当前frame/页面和使用的过滤条件，不能推广成整个系统无错误。成功快照不证明全部字段无误，网络成功不证明UI正确。

每项结论绑定版本、测试环境、前提、步骤、预期、实际及最小证据。报告中区分工具执行、传输成功、页面呈现和业务正确性，不跨层替代。

总计只汇总判据相同的用例。确有待确认项就分别列出PASS/FAIL/BLOCKED/NOT_TESTED/INCONCLUSIVE，不能为了“全通过”隐去未决问题。用户转述的现场结果要标注来源，不冒充本手册作者亲自复现。

## 8. 用稳定性目标代替固定窗口数

连接管理的目标是复用既有逻辑会话、没有无意新增客户端和标签页，不是所有任务永远只能一个窗口一个tab。获准弹窗、下载或多页流程可以合理增加页面；清理也不能通过强行关闭业务页来凑数量。

连接终止与页面关闭是两种操作；后台运行、Token、资料复用、会话复用分别解决不同问题。诊断前先确定故障属于哪一层，不能把所有行为异常都归因于连接生命周期。

## 最短模型执行规则

**先核身份和范围；输入后核对有效值；条件就绪再操作；动作后按预期核对内容；证据不足明确未判定。**

## 官方依据与验证范围

- [同源定义（MDN）](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy)：路径不参与源的scheme/host/port比较。
- [Playwright定位](https://playwright.dev/docs/locators)：语义、范围和唯一性。
- [Playwright frame](https://playwright.dev/docs/frames)：主frame与嵌套frame。
- [Playwright自动等待](https://playwright.dev/docs/actionability)：可操作性与业务结果的区别。
- [组件事件契约的官方示例](https://element-plus.org/en-US/component/date-picker.html#events)：确认与失焦等事件行为取决于组件契约；该文档不证明目标站点的具体版本或实现。

本文仅提炼规则和校正文义，没有访问目标企业页面、读取业务资料或复跑现场用例，也不添加默认运行代码/测试框架。
